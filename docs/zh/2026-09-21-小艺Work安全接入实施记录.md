## 已实现内容

core 新增可选 `defer_unmatched` / `PermissionLevel.UNDETERMINED`、`ToolPermissionHost.on_permission_evaluated`、`before_skill_install` 扩展。显式本地结果不会被外部观察回调覆盖，未判定且外部失败归 ASK。既有工具前后生命周期复用；`ToolCallInputs.execution_started` 补充“确实开始调用”标记，避免把拒绝、确认中断或被其他护栏跳过的调用当作工具输出。

Swarm 使用框架回调采集原始工具参数、结果、真实会话 ID、对话文本和技能准备信息，经已有 Windows 命名管道通信。框架不拼云端 body 和鉴权。新桌面通过能力环境变量显式启用该接入，替代该路径的旧 CSPL 调用，避免重复上报。未知行为的同步请求兼作记录，不另外异步发一次。

Agent 的 `install_skill` 四个 source（builtin、ClawHub、TeamSkillsHub、SkillNet）在替换前接入。SkillNet 工作线程回到原事件循环决策；拒绝/需要确认不会先覆盖旧文件。安装确认复用框架权限卡和恢复机制，同意一次不被误保存为工具的永久允许。内部内容摘要仅用于防止授权后内容变化，不是云端 hash 字段的既定口径。

desktop 独立接收原始行为，生成 `WINPC_XIAOYI_WORK` / `isXiaoyiAPP` / `toolInput`、`toolOutput`、`toolSkill` 格式；共用既有风控 HTTP、鉴权、区域和代理实现，skill ID 使用 `moderation-text`。纯上报采用有界后台任务，202 只表示本机接受。授权失败返回 unavailable，端侧转用户确认。CLARIFY 暂无已确认问题字段及完整往返链路，按需求允许本次，不猜测 remind 的含义。

配置位于 `jiuwenswarm/resources/config.yaml` 模板和用户 `config.yaml` 的 `xiaoyi_work_security.cloud_authorization.enabled`，默认 false。`permissions.enabled=false` 保持既有不校验语义，仍采集上报。
