# 技能安装安全自测

## 当前能测到哪里

当前源码及 9 月 21 日 debug 包的 `SkillToolkit.get_tools()` 都过滤了 `search_skill` 和 `install_skill`。安装方法存在，但没有注册为 Agent 可调用工具。因此，当前包不能通过聊天触发 `install_skill`；此前“直接让 Agent 安装测试技能”的手测说明遗漏了这个入口限制。

本次不修改已有工具开放策略。下面的脚本直接测试真实 SkillToolkit、SkillManager 和安装前安全检查，模拟 desktop 返回的风控决定。它能证明安装门禁的行为，不能证明桌面工具注册、真实权限卡或蓝区接口验收。

## 测试技能

仓库文件：`tests/fixtures/skills/xiaoyi-security-smoke/SKILL.md`。这是唯一需要的技能文件，无脚本、无依赖、无网络调用。

```text
xiaoyi-security-smoke/
└── SKILL.md
```

SKILL.md 的元数据名称为 `xiaoyi-security-smoke`，版本为 `1.0.0`；技能使用时只应回复 `XIAOYI_SKILL_INSTALL_OK`。安装测试本身不需要执行技能正文，也不需要制造恶意内容来触发风控。

测试脚本将该目录复制到每个测试的临时 builtin 来源，目标是另一处临时 `workspace/skills`。不要预先把源目录复制到目标目录，否则绕过安装流程，而且可能直接得到“已经安装”。

## 一条命令运行

在 PowerShell 执行：

```powershell
& 'C:\Users\newcs\.codex\worktrees\xiaoyi-behavior-security\jiuwenclaw\scripts\test_xiaoyi_skill_install.ps1'
```

脚本默认使用这台机器原始 Swarm 工作区的 Python 虚拟环境和此次 core worktree；其他机器可以通过 `-PythonExe`、`-CoreRoot` 指定路径。它在临时目录创建数据根，执行后恢复调用终端的环境变量，不写入小艺 Work 的已安装技能目录。

预期共 7 项通过。终端会输出 `Test artifacts: ...`，可到该目录查看临时技能源和安装结果。

| 场景 | 断言 |
|---|---|
| 模拟 allow | 实际安装成功，目标 SKILL.md 与源文件一致，安装状态已登记 |
| 模拟 deny | 安装失败，目标目录不存在，未登记安装成功 |
| 模拟 unavailable 后同意 | 首次停在安装前；恢复同意后通过门禁，同一安装事件不重复请求 |
| 模拟 unavailable 后拒绝 | 首次停在安装前；恢复拒绝仍不能通过，旧文件不变 |
| core 回调链 | 安装确认通过实际回调框架传播为 ToolInterruptException |
| SkillNet 工作线程遇到 deny | 不覆盖原有同名技能 |
| SkillNet 工作线程遇到 unavailable | 不覆盖原有同名技能，转用户确认 |

其中 unavailable 测试的是失败决定到本地确认的逻辑；没有调用真实云端，也没有用真实网络延迟制造超时。core 回调链测试不等于 Electron 权限卡验收。传输超时、云端响应格式和 body 拼装还有其他独立测试。

## 入口开放后的界面测试

产品侧先明确 Agent 安装入口是否允许开放，并将确定的入口打入 debug 包。当前单靠准备 SKILL.md 无法消除这个前置条件，也不能用技能市场按钮、本地导入或手工复制来替代验收这条调用链。

如果开放的是已有 builtin 安装路径，参数形状如下。`identifier` 是 builtin 来源中的技能名称，不是本地 zip 路径；当前工具只接受 `builtin`、`skillnet`、`clawhub`、`teamskillshub` 四种来源，没有 `source=local`。

```json
{
  "identifier": "xiaoyi-security-smoke",
  "source": "builtin",
  "timeout_sec": 60
}
```

应先确保源技能在 builtin 来源中、目标技能尚未安装，然后发送：

> 请调用 install_skill，identifier 为 xiaoyi-security-smoke，source 为 builtin。只执行安装，不要使用技能，不要通过写文件或命令行手工复制来代替安装。如果工具不可用，请直接说明。

验证顺序：先关闭云授权验证用户同意/拒绝；再开启云授权，配合云端可控测试响应验证 ACCEPT、REJECT、CLARIFY 和失败兜底。工具输入为 toolInput，安装前为 toolSkill，是不同接入点；在工具输入阶段就拒绝时，不应期待进入安装前事件。

当前 `toolSkill.questionText.file=[]`，文件上传对象、hash、size 和正文口径仍待定，本测试不覆盖附件风控。云端上报成功需要真实请求结果或云端记录，不能用本机测试通过代替。
